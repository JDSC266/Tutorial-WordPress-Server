# Cloudflare Tunnel desde el panel

Esta guia usa el Panel de Control de Cloudflare Zero Trust para crear y administrar el tunel.

En este metodo, no configuras los hostnames ni los servicios desde un archivo `config.yml` en tu servidor. El servidor solo instala y ejecuta el conector `cloudflared` con el token que Cloudflare te entrega. Las rutas como `justecno.com` o `cv.justecno.com` se manejan desde el panel.

Ejemplo:

```text
https://justecno.com      -> http://localhost:80
https://cv.justecno.com   -> http://localhost:80
```

Esto sirve perfecto para WordPress Multisite, porque ambos dominios llegan al mismo servidor y WordPress decide que sitio mostrar.

---

## 1. Que vas a configurar

Arquitectura:

```text
Visitante
  |
  v
Cloudflare HTTPS
  |
  v
Cloudflare Tunnel administrado desde el panel
  |
  v
Servidor local o VPS
  |
  v
Apache2, Nginx u OpenLiteSpeed en localhost:80
  |
  v
WordPress o WordPress Multisite
```

Importante:

- No abres puertos en el router.
- No creas reglas NAT en tu modem.
- No necesitas configurar HTTPS en Apache2/Nginx/OpenLiteSpeed para el acceso publico.
- Cloudflare gestiona los hostnames desde el panel.
- Tu servidor debe responder localmente en `http://localhost:80`.

---

## 2. Crear tunel en Cloudflare

Entra a:

```text
Cloudflare Dashboard > Zero Trust
```

Luego:

```text
Redes > Conectores > Cloudflare Tunnels > Crear tunel
```

Pasos:

1. Selecciona `Cloudflared`.
2. Asigna un nombre al tunel, por ejemplo:

```text
wordpress-server
```

3. Continua hasta `Instalar y ejecutar un conector`.

---

## 3. Instalar y ejecutar el conector

En la pantalla como la de tu captura, Cloudflare te muestra comandos segun:

- Sistema operativo: Debian, Ubuntu, Windows, macOS, Docker, etc.
- Arquitectura: 64-bit, ARM, etc.

Selecciona:

```text
Debian
64-bit
```

o la opcion que corresponda a tu servidor.

Cloudflare mostrara un bloque parecido a este:

```bash
# Add cloudflare gpg key
sudo mkdir -p --mode=0755 /usr/share/keyrings
curl -fsSL https://pkg.cloudflare.com/cloudflare-public-v2.gpg | sudo tee /usr/share/keyrings/cloudflare-public-v2.gpg >/dev/null

# Add this repo to your apt repositories
echo "deb [signed-by=/usr/share/keyrings/cloudflare-public-v2.gpg] https://pkg.cloudflare.com/cloudflared any main" | sudo tee /etc/apt/sources.list.d/cloudflared.list

# install cloudflared
sudo apt-get update && sudo apt-get install cloudflared
```

Despues te mostrara un comando con token, parecido a:

```bash
sudo cloudflared service install TOKEN_MUY_LARGO
```

Ejecuta ese comando en tu servidor.

> Guarda ese token con cuidado. Cualquier persona con ese token podria conectar un servidor a tu tunel.

---

## 4. Verificar que el conector esta activo

En el servidor:

```bash
systemctl status cloudflared
systemctl is-active cloudflared
```

En el panel de Cloudflare, el conector debe aparecer como:

```text
HEALTHY
```

Si aparece desconectado, revisa:

```bash
sudo journalctl -u cloudflared -f
```

---

## 5. Enrutar el dominio principal

En el asistente de Cloudflare, ve a la parte:

```text
Enrutar tunel
```

Agrega un Public Hostname:

| Campo | Valor |
|---|---|
| Subdomain | vacio |
| Domain | `tudominio.com` |
| Path | vacio |
| Type | `HTTP` |
| URL | `localhost:80` |

Guarda.

Resultado:

```text
https://justecno.com -> http://localhost:80
```

---

## 6. Enrutar www

Agrega otro Public Hostname:

| Campo | Valor |
|---|---|
| Subdomain | `www` |
| Domain | `tudominio.com` |
| Path | vacio |
| Type | `HTTP` |
| URL | `localhost:80` |

Resultado:

```text
https://www.tudominio.com -> http://localhost:80
```

---

## 7. Enrutar subdominio para Multisite

Para el segundo sitio de WordPress Multisite:

```text
https://cv.tudominio.com
```

agrega otro Public Hostname:

| Campo | Valor |
|---|---|
| Subdomain | `cv` |
| Domain | `tudominio.com` |
| Path | vacio |
| Type | `HTTP` |
| URL | `localhost:80` |

Resultado:

```text
https://cv.tudominio.com -> http://localhost:80
```

WordPress Multisite se encargara de mostrar el sitio `cv`.

---

## 8. Usar wildcard para muchos subdominios

Si vas a crear muchos sitios en Multisite:

```text
cv.tudominio.com
blog.tudominio.com
tienda.tudominio.com
```

puedes crear un hostname wildcard si tu configuracion de Cloudflare lo permite:

| Campo | Valor |
|---|---|
| Subdomain | `*` |
| Domain | `tudominio.com` |
| Path | vacio |
| Type | `HTTP` |
| URL | `localhost:80` |

Resultado:

```text
https://*.tudominio.com -> http://localhost:80
```

Si el panel no acepta wildcard en tu cuenta o plan, crea cada subdominio manualmente como Public Hostname.

---

## 9. Configuracion del servidor web

Aunque Cloudflare maneje el tunel, tu servidor web debe aceptar esos dominios.

### Apache2

En el VirtualHost:

```apache
ServerName tudominio.com
ServerAlias www.tudominio.com *.tudominio.com
```

### Nginx

En el server block:

```nginx
server_name tudominio.com www.tudominio.com *.tudominio.com;
```

### OpenLiteSpeed

En el Virtual Host Mapping:

```text
Domains: tudominio.com, www.tudominio.com, *.tudominio.com
```

---

## 10. Configuracion de WordPress detras de Cloudflare

Como Cloudflare entrega HTTPS por fuera, pero el servidor recibe HTTP local, WordPress puede creer que esta en HTTP.

Agrega en `wp-config.php`, antes de `/* That's all, stop editing! */`:

```php
if ( isset( $_SERVER['HTTP_CF_VISITOR'] ) && strpos( $_SERVER['HTTP_CF_VISITOR'], 'https' ) !== false ) {
    $_SERVER['HTTPS'] = 'on';
}
```

Tambien revisa:

```text
Ajustes > Generales
```

Valores recomendados:

```text
Direccion de WordPress: https://tudominio.com
Direccion del sitio: https://tudominio.com
```

En Multisite, revisa los sitios desde:

```text
Mis sitios > Administrador de la red > Sitios
```

---

## 11. Verificar desde el servidor

Prueba que el servidor responde localmente:

```bash
curl -I http://localhost -H "Host: tudominio.com"
curl -I http://localhost -H "Host: cv.tudominio.com"
```

Debe responder algo como:

```text
HTTP/1.1 200 OK
```

o una redireccion esperada de WordPress.

---

## 12. Verificar desde internet

Abre en el navegador:

```text
https://tudominio.com
https://www.tudominio.com
https://cv.tudominio.com
```

Si `tudominio.com` funciona pero `cv.tudominio.com` no:

1. Revisa que el Public Hostname `cv` exista en Cloudflare.
2. Revisa que el sitio `cv` exista en WordPress Multisite.
3. Revisa que Apache2/Nginx/OpenLiteSpeed acepte `*.tudominio.com`.
4. Revisa logs de `cloudflared`.

---

## 13. Diferencia con el metodo por terminal

| Metodo | Donde configuras rutas |
|---|---|
| `07.1 - Cloudflare Tunnel por terminal` | En el servidor, con `config.yml` y comandos `cloudflared tunnel route dns`. |
| `07.2 - Cloudflare Tunnel desde el panel` | En Cloudflare Zero Trust, usando Public Hostnames. |

Para principiantes, el metodo del panel suele ser mas comodo porque Cloudflare te da el comando exacto con token y maneja los hostnames visualmente.
